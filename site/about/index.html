The problem

A satellite is overhead for ten minutes or so, and that pass never comes again. Whatever a station misses is gone. Yet most stations choose passes by one rule, how high the satellite climbs, and nothing checks afterwards whether the choice was right.

What Meridian does

It predicts which passes will really return data, plans every station's time around that, checks each recording, and explains each loss. Every figure it publishes can be rebuilt by anyone from the same data. How it works shows the steps, and the architecture shows the parts.

Open to any station

A station joins by speaking MSP, Meridian's open protocol, not by running our code. It is small enough to build into a microcontroller in an afternoon.

Three rules

  • Stations only listen. Nothing in Meridian transmits, and nothing ever will.
  • Simulated is always labelled simulated. Practice data is marked as such everywhere, and never mixed with real results.
  • No outside service is needed to run. If every external service went offline, Meridian would still plan, receive and report with its own stations.

Where it stands

The software is built and tested, and a practice fleet of 50 simulated stations runs it today. The first real station is being built; until it has received, this site shows no measured results, because there are none. Meridian began as a final-year engineering project, built by a team of three, and is written to outlast it.

Taking part

Read the protocol and tell us where it is wrong, or run a station and join. Technical questions go to GitHub issues, where the next person can find the answer. Anything else goes to hello@meridian.org.in.
